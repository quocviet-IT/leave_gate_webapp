# Leave & Gate Pass — Delivery Roadmap

**Source spec:** [docs/PRD_Nghi_Phep_Ra_Vao_Cong.html](../../PRD_Nghi_Phep_Ra_Vao_Cong.html) v0.5
**Scaffold:** commit `5309f5e` — routes, auth boundaries, domain logic, migrations 0001–0002 live

This roadmap orders the work and fixes the quality bar. Each phase gets its own
detailed plan under `docs/superpowers/plans/`, written when the previous phase
lands, so a plan never goes stale before it is executed.

---

## Ordering principle

Phases run **easiest first, but only where "easy" also means "unblocking"**. The
PRD's own build order puts Directory sync at step 2; this roadmap moves it to
P9 and starts with a manual employee import instead. The reason is in the PRD
itself (section XV): the team may work from a provisional staff list while HR
prepares the real one. That single change unblocks every screen without waiting
on a Google service account or an HR data project.

| Phase | What it delivers | Hard part | Externally blocked |
| --- | --- | --- | --- |
| **P1** | Employee master data: paste-import, name search | none — pure data | no |
| **P2** | Public form, one route, dynamic fields, filing works | identity without a login | no |
| **P3** | Lookup page: track, withdraw, real return time | authorising a read without a session | no |
| **P4** | Approval queue: claim, version lock, live refresh, tabs | concurrency between four people | no |
| **P5** | Gate booth: PIN session, stamps, 5-minute undo | shared-device session, tap targets | booth machine + PIN |
| **P6** | Timesheet: filters, gate-time column, adjustments, Excel | audit trail that cannot be bypassed | no |
| **P7** | Overview screen; supervisors filing on behalf | department scoping | supervisor list |
| **P8** | Two Chat spaces, SLA reminder job | working-hours scheduling | webhook URLs |
| **P9** | Directory sync replaces the import | one-way reconcile without wiping data | service account |
| **P10** | Print layouts matching the paper forms | diacritics, page breaks | no |
| **P11** | Hardening: performance, accessibility, full-journey E2E | proving the budgets hold | no |

P1–P4 is the spine: after P4 a request can be filed on a phone and decided by
an approver. Everything after that adds a zone or a report on top of a system
that already works end to end.

## Global constraints — every phase inherits these

Copied from the PRD and from the two repo rulebooks. A task that violates one of
these is not done, however well it works.

### Language

- Everything a user reads: **Vietnamese**. Code, identifiers, comments, commit
  messages, these plans: **English**.
- Money and hours use the Vietnamese decimal comma at the UI edge (`3,3 giờ`).

### Zone-scoped dependency budget

The public zone opens on a worker's phone on factory wifi, so it does not get to
be heavy:

| Zone | Ant Design | First-load JS budget (gzip) |
| --- | --- | --- |
| `/`, `/don`, `/tra-cuu` | **not allowed** — plain HTML, CSS, and hand-written inputs | **≤ 60 KB** |
| `/admin/*` | allowed | ≤ 320 KB |
| `/bao-ve` | allowed | ≤ 220 KB |

Measured with `npm run build`; the route table prints First Load JS per route.
Exceeding a budget fails the phase.

### Performance

- Public form interactive in **≤ 1.5 s** on a throttled Fast-3G profile.
- Every database read behind a screen: **one round trip**, no N+1. Details are
  joined in the same query or fetched by a single `in (...)`.
- The approval queue and the booth table refresh over Supabase realtime, never
  by polling.
- The booth table is capped at today's rows; the timesheet paginates at 50.
- No `select *` on a table that carries a lookup token or a PIN hash.

### Security invariants

- `anon` never receives a table policy. Public reads and writes go through
  SECURITY DEFINER functions that enforce the employee code and rate limits.
- The lookup token is never logged, never put in a page title, and never sent to
  an analytics or error-reporting sink.
- A booth screen never renders a leave reason, and never a leave request.
- Hours computed by `lib/domain/workhours.ts` are written once and never edited;
  payroll edits go to a separate column with a mandatory reason.
- Every state change records who and when. Nothing is deleted.

### UI/UX standards

- **Public zone:** one screen, one job. Name and code above the fold. Tap
  targets ≥ 44 px. Errors inline under the field, in plain Vietnamese, saying
  what to do next — never a code or a stack trace. The computed hours line
  updates as soon as dates change, so the person sees the number before sending.
- **Booth:** built for a fingertip on a shared, possibly old screen. Two buttons
  per row, ≥ 56 px tall, ≥ 16 px text, contrast ratio ≥ 4.5:1. No modal ever
  stands between the guard and the button.
- **Admin:** summary before detail. State carried in shape as well as text — a
  pill, a colour, a countdown — so what needs attention reads at a glance.
- Loading states are skeletons of the real layout, not spinners over a blank page.
- Keyboard focus is always visible; every icon-only control carries an aria-label.
- `prefers-reduced-motion` is respected.

### Verification gates (per phase, all mandatory)

1. `npm run build` · `npm test` · `npm run typecheck` · `npm run lint` — zero errors, output pasted.
2. `node scripts/smoke-pages.mjs http://localhost:PORT` — every route answers per zone.
3. A `scripts/verify-<phase>.mjs` end-to-end script that drives the real
   database over HTTPS and asserts the business rules of that phase, then cleans
   up after itself.
4. First Load JS for every touched route is inside its zone budget.
5. Every PRD business rule the phase claims is covered by a named test.

## Business rule coverage

PRD section XIII has 20 rules. Each is owned by exactly one phase, so nothing
falls between them.

| Rule | Phase | Enforced where |
| --- | --- | --- |
| 1 · filing needs no login, reading does | P2, P3 | `lg_submit_request`, `lg_lookup_request` |
| 2 · names chosen from the list | P1 | `lg_search_employees`, no free-text name column |
| 3 · code must match; 5 tries; 5 a day | P2 | `lg_submit_request` + `lg_submit_attempt` |
| 4 · admin zone is company accounts only | done | `lib/auth.ts`, `lg_current_role()` |
| 5 · four approvers cover all staff | P4 | `lg_request_read` policy |
| 6 · supervisors file, never approve | P7 | `lg_file_on_behalf`, role check |
| 7 · claim before deciding; 30-minute release | P4 | `lg_claim_request`, `lg_release_stale_claims` |
| 8 · one approval; stale action refused | P4 | version match in `lg_decide_request` |
| 9 · nobody approves their own | P4 | email comparison in `lg_decide_request` |
| 10 · rejection may carry a reason | P4 | `decisionSchema` |
| 11 · withdraw a pending request | P3 | `lg_withdraw_request` |
| 12 · approved requests are not edited | P6 | `lg_cancel_approved` only |
| 13 · guard time beats declared time; 5-min undo | P5 | `lg_stamp_gate`, `lg_undo_stamp` |
| 14 · booth sees today's approved passes only | P5 | `lg_booth_today` |
| 15 · real return due end of next working day | P3 | `endOfNextWorkingDay` + `lg_set_actual_return` |
| 16 · final-hours edit needs a reason | P6 | `lg_set_final_hours` + `lg_hours_adjustment` |
| 17 · computed hours locked | P6 | no update path exists |
| 18 · nothing deleted | all | no `delete` in any function |
| 19 · Chat messages carry no leave reason | P8 | message builders + their tests |
| 20 · SLA counts working hours only | P8 | `lib/domain/sla.ts` (already tested) |
