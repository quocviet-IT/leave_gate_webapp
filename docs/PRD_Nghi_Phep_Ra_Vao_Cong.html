Leave Application & Gate Pass System

Replaces the two paper forms in use today with an internal web app. Employees open a link or scan a QR code to file a request — no login; one of the four approvers claims and decides it; the guard confirms the real times at the gate; approved requests flow straight to the timesheet screen.

0What changed since v0.4

v0.6 — the filing screen is fully open. v0.5 asked the employee to type a matching employee code, treating it as a stand-in for a password. That is gone: the name is picked from the staff list and the form sends. The employee number survives only as the row key of the staff import, never shown and never asked for.

Three consequences follow, and all three are written into the rules below rather than left implied: ① the request code the system issues is a reference, not a key — it is sequential, so quoting it may reveal a status and nothing more, while name, dates and reasons need the private link issued at filing (rule 1); ② the form is held by rate limits instead of a credential (rule 3); ③ nothing now waits on HR producing an employee-code mapping — the only prerequisite left is a spreadsheet of staff that C&B can paste in.

IIIThree experience zones

The app splits into three separate zones, each with its own way in and its own users. They are split because the three groups have nothing in common: workers need to get in with no obstacle, approvers need full data under proper control, and guards need a single table they can operate with a fingertip on a shared machine.

Employee zone · public

/don · /tra-cuu
  • No login. Open a link, or scan the QR code posted in the workshops and on noticeboards
  • One form; the first field picks the type and the fields below change to match
  • Identified by choosing a name from the synced list — nothing to type, nothing to remember
  • Filing returns a request code and a private tracking link
  • The lookup page: check status, withdraw a pending request, enter the real return time, print an approved request

Admin zone · /admin

/admin/tong-quan · /duyet-don · /cham-cong
  • Sign in with the company Google account; domains other than @ctyhp.vn are refused
  • Overview: pending requests, overdue requests, leave hours in the period, requests not yet on a timesheet
  • The approval queue, with the Claim button and four personal tabs
  • Timesheet screen: filter by period, two hours columns, Excel download, mark as done
  • Supervisors filing on behalf of workers in their own department

Gate booth · /bao-ve

/bao-ve
  • Opens with the booth PIN; the session lasts weeks so a shift change needs no sign-in
  • One table: today's approved gate passes
  • Two large buttons per row — Cho ra and Cho vào — one tap records the time
  • Read-only otherwise: no edits, no decisions, and no leave reasons

VIISplitting work between four approvers

On paper there is one sheet, so two people can never sign at once. In the app all four approvers watch the same queue, so something has to guarantee that one request is handled by one person — and that no request sits untouched because each approver assumes another took it.

Four mechanisms

MechanismHow it worksWhat it prevents
ClaimNhận xử lý Every row carries a Nhận xử lý button. Once tapped the request moves to Đang xử lý with a name and a timestamp, and the other three see the row greyed out and labelled "Chị Diệu đang xử lý". A claim returns to the queue after 30 minutes without a decision. The holder can also release it. Four people opening one request
Version lockOptimistic locking Each request carries a version number that increases on every state change. The approve action sends the version on screen; if it no longer matches, the system refuses the action and shows "Chị Trân approved this at 09:31". The check lives in the database, not only in the interface. Two decisions overwriting each other
Live refreshReal-time The queue subscribes to database changes. A request being claimed, decided or withdrawn appears on every other screen at once, with no reload, and the pending count in the menu follows. Acting on figures that are already stale
Timed remindersSLA Counted from filing, in working hours only. One hour brings a gentle nudge to the approvers' space; two hours brings a second naming all four. A claimed request stops the clock. Requests sitting still because everyone assumes someone else has it

Claiming is not a hard assignment. Nobody is allocated a request automatically, and all four approvers keep equal authority over all staff. The mechanism exists only so four people do not collide; if the holder steps away, the request returns to the queue after 30 minutes.

XIIIBusiness rules

  1. 1Filing needs nothing; reading in full needs the private link. The public form only accepts requests. The request code is sequential, so quoting it answers with a status only — never a name, a date or a reason.
  2. 2Names are chosen from the list, never typed. The list comes from the staff records; people who have left no longer appear.
  3. 3The public form is rate-limited, not gated. Nothing an employee types is treated as a credential. Limits: at most 5 requests per employee per day and one per minute per device. Anyone can therefore file under another person's name, and the four approvers are the control point — see the note under these rules.
  4. 4The admin zone accepts company accounts only. Domains other than @ctyhp.vn are refused at the account picker.
  5. 5All four approvers have authority over all staff, with no split by department.
  6. 6Supervisors may file, never approve. Only for their own department; the request records who filed it and still goes to the four approvers.
  7. 7A request must be claimed before it can be decided. An unresolved claim returns to the queue after 30 minutes.
  8. 8One approval is enough. Acting on stale data is refused, and the message names who decided it and when.
  9. 9Nobody approves their own request. An approver's own request hides the approve button and goes to the other three — matched on the account email.
  10. 10A rejection may carry a reason — not required, but with one the employee knows what to change.
  11. 11Employees may withdraw a pending request, even after someone has claimed it. The withdrawal is posted to the Chat space so nobody decides a withdrawn request.
  12. 12An approved request cannot be edited. To change one, Chị Khoa cancels it with a reason and the employee files again.
  13. 13The guard's time at the gate beats the employee's own. A mis-tap is undoable for 5 minutes; after that Chị Khoa edits it with a reason.
  14. 14The booth sees only today's approved gate passes, never a leave reason and never a leave request.
  15. 15The real return time is due by the end of the next working day. After that the employee's field locks and only Chị Khoa can edit it.
  16. 16Editing the final hours requires an adjustment reason of at least 10 characters. Every edit keeps the old value, new value, editor, timestamp and reason.
  17. 17The computed hours are locked and cannot be edited by anyone — including Chị Khoa.
  18. 18Nothing is deleted. Withdrawals and cancellations only move a status; every action records who and when.
  19. 19Google Chat messages never carry a leave reason, in either space.
  20. 20SLA reminders count working hours only. The clock stops in the evening and on Sundays, so nobody is paged during time off.
The known weakness, stated plainly: with nothing to prove who is filing, anyone who can open the link can file under another person's name. This is the accepted price of a form a worker can use in ten seconds without a company email. What stands against it: names come only from the staff list, a daily cap per person, every request carrying its filing time and device fingerprint in the audit log, and — the real control — four approvers who know the staff and their departments. To make that control usable, the approval screen shows the person's recent requests beside the one being decided, so a duplicate or an out-of-character pattern is visible without going looking for it.

The residual gap is that an impersonated employee has no way to discover a request filed in their name, because they never received its link. If the board wants that closed, the options are a company email for everyone (then sign-in replaces this entirely) or a shared department PIN at the top of the form.

2Staff master data: C&B pastes the list, the public form can search it; authorisation for all three zones; load the four approvers, Chị Khoa and the supervisors
3The public form: one route, dynamic fields, name picked from the list, with the hours computed live and the rate limits in place
4The lookup page: track, withdraw, enter the real return time; request codes, private links, QR codes
5The approval queue: Claim, version lock, live refresh, four tabs, no self-approval
6The gate booth: PIN, today's table, Cho ra / Cho vào, 5-minute undo
7The timesheet: filters, gate-time column, two hours columns, mandatory adjustment reason, Excel, mark as done
8The overview screen; supervisors filing on behalf
9Two Google Chat spaces and the 1 h · 2 h reminder job
10Print layouts matching the paper forms
11One end-to-end run: file on a phone → approve → guard taps at the gate → timesheet; then go live with a one-page guide and QR codes for the workshops
Still missing before work can start: ① the official list of departments and units; ② the staff list itself, in any spreadsheet C&B can paste from; ③ the list of supervisors allowed to file on behalf; ④ a PIN for the booth and confirmation that the booth has a networked machine. Without ② step 3 cannot run. Until then the team works from a provisional list and swaps in the real one.

RiskLevelHandling
Without a staff list, nobody can be chosen on the public form High C&B pastes any spreadsheet of staff into the admin zone; re-pasting updates in place. Needed before step 3, but it is a spreadsheet, not a project
Anyone with the link can file under another person's name High A cap of 5 requests per employee per day and one per minute per device; only names in the staff list can be chosen; every filing logged with its device fingerprint; the approval screen shows the person's recent requests so an odd pattern is visible. Accepted residual risk: the impersonated person cannot discover the request themselves. Closing it needs company email for everyone, or a shared department PIN on the form
The booth PIN spreads and non-guards can open the table Medium The table holds only today's approved passes and no leave reasons, so the exposure is bounded. Chị Khoa can change the PIN at any time; named sign-in per guard is Phase 2
The booth has no networked machine, or loses the network mid-shift Medium Confirm the booth's setup before going live. During an outage the guard uses the shift logbook and Chị Khoa keys it in with a reason. Offline mode is Phase 2
The guard forgets to tap, so the times fall back to what the employee declared Medium The timesheet screen counts missing gate times so Chị Khoa sees them at once; such requests are flagged rather than passing quietly
All four approvers are busy and requests wait too long Medium Reminders at 1 h and 2 h to the Chat space, the Quá hạn tab, and a counter on the overview screen. Escalation above the four is not in Phase 1
An approver claims a request then steps away, holding it hostage Low The claim expires after 30 minutes and the other three see the Claim button again
Phase 1 does not deduct public holidays Medium Chị Khoa edits the final hours with a reason when leave overlaps a holiday. A holiday calendar is Phase 2
A shared Chat space means everyone in it sees who is asking for leave Medium Messages carry only name, type, dates and a link — never a reason. The approvers' space holds just the four approvers and Chị Khoa; the guards' space receives gate passes only
The Directory is missing job titles or departments, so the form shows "—" Medium Audit the Directory before going live. Requests still file with an empty field and Chị Khoa fixes it later; empty fields raise a warning for HR
The public form is spammed from outside the company Low Only names in the staff list can be chosen, so junk cannot invent a person; limits apply per employee per day and per device per minute; the address is internal and not linked from anywhere public
Adding or changing a supervisor or approver needs the development team Low Rare. An HR-facing role admin screen is Phase 2
